## 1. The method, and why it is this method

`CONSTITUTION.md` §3 already states the law ("reduce lines, never reduce meaning") and
`Projects/deepseek-harness/docs/AGENTS.md` already carries a nine-item slop checklist. Both were
prose; nothing measured the workspace. This pass made the law executable and grounded its judgement
in three primary sources:

| Source | Finding | Rule it produced here |
|---|---|---|
| He, Zhao, Wang, Chen 2026, *Is Progressive Disclosure All You Need for Long-Context Agents?* (arXiv:2607.17598) | One disclosure level is enough; a second routing level **never** helps and sometimes collapses accuracy (En.MC 0.9126 → 0.6398 on Pi/gpt-5.4-mini). "Progressive disclosure buys context, not intelligence." | A context doc links **once** to the owning home. It never re-indexes its grandchildren. |
| Gloaguen et al. 2026, *Evaluating AGENTS.md* (arXiv:2602.11988) | Repository context files tend to **lower** task success and raise inference cost **over 20%**; agents faithfully obey even instructions they did not need. | **Burden of proof per line:** a line must remove a fact the agent cannot discover, or an ambiguity it would otherwise resolve wrongly. A line that restates a fact owned elsewhere has *negative* value. |
| Liu et al. 2024, *Lost in the Middle* | Use of context is U-shaped in position; the effective window is far below the advertised one. | Invariants belong near the top; prose padding in the middle costs signal. |

These three rules are the whole of the tool's judgement. Everything else it does is counting.

## 6. Tool defects found and fixed in this session (all caught by the tool's own tests)

Kept on the record because the tool's whole claim is that it can be believed:

1. `${!arr[@]+"${arr[@]}"}` is parsed by bash as an indirection and **printed the array's values** as
   invalid variable names — the duplicate detector silently produced nothing. Fixed with a
   `${#arr[@]} -gt 0` guard.
2. `for k in $(...)` word-split the normalized duplicate keys (they contain spaces), so every key
   was compared in fragments. Fixed with a `while IFS= read -r` loop.
3. `HOME_DIR="${HOME}"` clobbered the environment override the self-test depends on.
4. The tool demanded `CONSTITUTION.md` exist while never reading a byte of it — so its own fixture
   mode died with `source not found`. The real path is now threaded through the fixture runs.
5. The self-test wrote its fixture to `$tmp/proj` but declared `fixture/proj`: every row was
   `MISSING`, so it tested nothing while appearing to. **The known-positive rule is what exposed
   this**: the assertions failed instead of passing vacuously.
6. The fixture heading was 7 characters, below the detector's 12-character floor, so the duplicate
   detector was never exercised. Fixed, and a duplicate-invariant assertion added.
7. `load_protected` read **every column** of a `PROTECTED.md` — including the "Safe write-path"
   section, which is the exact opposite of protected — producing **6 false `CONFLICT` rows** that
   claimed editable documents were protected. Fixed by scoping to the protected section and its
   first table column. This is the defect that would have caused the most damage: it inverted the
   declaration it was reading.
8. `CAPS` counted identifiers and table cells (1362 "all-caps tokens" in one focused document) and
   `PREAMBLE` flagged a one-line paragraph. Both are now position-aware: fenced code, table rows
   and headings are excluded from emphasis density, and a preamble is only slop when its block runs
   past the two lines the doctrine allows.

## 12. Content digests — because size is not integrity

### The gap the crew loss exposed

The audit measured how *big* each declared document was. It could not tell whether the bytes were
still the bytes anyone had agreed to. That is precisely how `crew-research-council/PROTECTED.md`
disappeared: the surface stayed "26 documents", nothing was over ceiling, and a file that other
projects' law depended on was simply gone. A size budget is a budget; it is not a record.

### What was added

| artifact | what it does |
|---|---|
| `local/context/digests.tsv` | **recorded state, not law** — `path <TAB> sha256 <TAB> words` for every declared document |
| `context-audit.sh --record` | pins the surface: recomputes every digest and writes the file. This is the explicit *"I intend this change"* act |
| `context-audit.sh --digests` | the table: `ok` / `DRIFT` / `NEW` / `GONE` per document, recorded vs on-disk, 8-char each |
| `context-audit.sh --check` | a digest failure now fails the gate alongside a ceiling breach or a missing file |

Two rules make it more than a checksum list:

1. **Intentional change is a two-step act.** Edit the document; then `--record`; then say why in the
   receipt. A rewrite that skips the second step is `DRIFT`, and the gate says so instead of passing
   because the word count happened to stay in range.
2. **`--record` never drops a digest for a file that is gone.** It carries the old digest forward and
   prints `CARRIED <path>` to stderr. Without this, deleting a document and re-recording the surface
   would have *laundered* the deletion into a clean state — the exact edit-the-test-to-pass pattern
   this workspace's `E9` rule is about.

### Honest limits (stated, not implied)

- **Detection is not recovery.** Had this layer existed on 2026-09-20, the next `--check` would have
  shown `GONE` for the crew declaration instead of silence — but `GONE` restores nothing. The durable
  fix for recovery was `git` tracking (§11); the digest layer is what would have *told us in time*.
- **It cannot tell an authorised rewrite from an unauthorised one.** A digest proves the bytes did not
  change; only the receipt can say whether they were allowed to. The layer makes the question
  unavoidable, not answered.
- **`--record` is a local act.** Nothing yet binds it to the same commit as the edit it accepts, so a
  contributor who re-records and never commits leaves a surface that says "fine" while git says
  nothing. Binding the two is the next hardening.

## 9. Resume in one command

```
bash ~/local/scripts/context-audit.sh --self-test && bash ~/local/scripts/context-audit.sh --write
bash ~/local/scripts/context-audit.sh --check      # exit 0 when the last remaining doc lands
```

Counts are deliberately **not** restated here: `local/context/REGISTRY.md` is their one home, and the
surface moves — another session rewrote nine documents *during* this one. What is durable is the
shape of the state:

- **What this session did:** seven documents compressed (−514 words), one lost declaration restored and
  committed, one audit tool extended three times (density, digests, reconstruction-safe recording),
  every claim in this file carrying the command that produced it.
- **What is red, and the one command that clears each:** `knowledge-factory/design.md` is over its
  policy target, and its finish line is the four counters (`CITE=145`, `FALSE=12`, `NUM ≥ 78`,
  falling `WORDS`) rather than a percentage; the nine digest drifts come from a concurrent writer's
  batch and clear with `--record`, run by whoever made those changes.
- **Two project gates were executed and are green** — colony `npm run verify`, dyno-pony `preflight`
  17/17 with the full suite at 185/185. Every other gate in this file is named as *not run*, never
  assumed.

The verdict of round 2 on the policy itself: the mechanical part of context engineering is small and
finite — seven documents that looked like four thousand words of fat yielded five hundred, because the
rest was single-homed truth.

Round 3 changed the shape of what remains rather than its count. `design.md` is still red, still
6,369 / 5,080 — but it is no longer "blocked on an Owner"; it is **blocked on a measurable acceptance
test** (`CITE=145`, `FALSE=12` unchanged, `NUM ≥ 78`, `WORDS` falling), enforced by a tool flag added
in the same round. Three rounds have now each corrected one layer of the original policy — the word
target, the ceiling value, and the classification itself — and each correction came from a number on
disk rather than from a preference. That is the whole method: **a document is compressed until a
measurement says stop, and the measurement is written down.**

## 13. The commit binding — a re-record cannot bless a change no commit holds

### The hole, stated precisely
§12 armed content digests. A digest proves the bytes did not move behind the tool's back; it says
nothing about whether anyone decided. So `--record` pinned whatever was on disk, and the gate went
green on bytes that existed nowhere but that working tree: a checkout, a reset or a fresh clone would
take the document away and no line on disk would say so. Same shape as the crew loss in §11, one layer
up — unversioned bytes, lost.

The first refusing run found it: of the 26 declared documents, **10 that were pinned at 07:14 had no
commit holding them**, two of them (`knowledge-factory/README.md`, `knowledge-factory/PROTECTED.md`) with
digest `ok` — a silent blessing, already written down.

### What a row carries now
`digests.tsv` goes from three columns to six: `path · sha256 · words · blob · commit · bind`, where
`bind` is `committed` (the working tree equalled HEAD's blob for that path) or `no-repo`. `--digests`
and the registry gained a bind column.

**`--record` refuses; it does not warn.** A changed document that no commit holds is refused in both
forms: the working tree differs from HEAD, or the document sits outside version control entirely. A
refusal keeps the previous row and exits 1, so the surface cannot be re-recorded into a green gate. A
first pin of an out-of-git document is allowed, because it overwrites no state.

**`--check` re-derives the chain** and fails when a link breaks: the recorded commit is gone from the
repository, or no longer holds the recorded bytes for that path, or the working tree is not those bytes.
`NO-COMMIT` names a row recorded before this layer existed; `no-repo` is a `WARN`, not a failure, because
there is no commit to demand.

### Why a row cannot simply be forged
`blob` must equal `git rev-parse <commit>:<path>` for a commit that exists in that repository, and
`git hash-object` of the working file must equal the same `blob`. Editing `digests.tsv` by hand can
therefore bless only bytes a real commit already holds — never uncommitted bytes, and never bytes that
were never committed at all. The object store enforces this, not the ledger's own honesty.

### Evidence
* `--self-test` gained fourteen assertions: committed → bound; the same document edited without a commit →
  `--record` refuses, the row is byte-identical afterwards, and it is still `DRIFT`; the edit committed
  → accepted and bound; a changed out-of-git document → refused too; an unchanged out-of-git document →
  `WARN`, not a failure.
* Three mutation tests — `bind_verify` neutered, the uncommitted refusal removed, the out-of-git refusal
  removed — each produce a **FAIL naming the exact assertion**. The known-positive rule of §12's
  self-test, applied to the new layer rather than asserted for it.
* A live probe on the real surface: one byte appended to `Projects/dyno-pony/AGENT-ERGONOMICS.md` gave
  `REFUSED …working tree differs from HEAD`, `--record` exit 1, the row still `da838837`, `BIND=ok`.
  Restoring the bytes returned it to `ok/ok` and `git status` to clean.

### The uniform rule, found by my own mistake
The first `--record` under the new layer still blessed `anatomy-lab/PROTECTED.md`: its bytes had been
rewritten at 07:15:27 by the concurrent writer, and the document is outside any repository, so nothing
refused it — the same failure with the reason moved. The rule was therefore made uniform, and that one
row was **hand-repaired** back to its 07:14 recording (`9d7f96c1…` → `99b4cec7…`). It is the only hand
edit to generated state in this receipt, it is stated here, and it exists to restore a refusal that a
superseded rule had let through.

### Honest limits
* The tool never commits. `--record` refuses until the commit exists; making it is the Owner's act.
* A hand-editor can still add a *first* pin for an out-of-git document: the ledger is not signed, and it
  lives in `~/local`, which is itself not a version-controlled tree. Only rows inside repositories are
  protected by the object store.
* Refusal makes the gate red on purpose. Ten of the twelve refusals are another writer's uncommitted
  revisions; this session committed neither them nor its own superseded edits (§10).
